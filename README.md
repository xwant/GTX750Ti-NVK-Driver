# GTX 750 Ti / GM107 — NVK driver experiments

Исследование и экспериментальные модификации **Mesa NVK** для NVIDIA GeForce GTX 750 Ti (Maxwell GM107). Base и первый патч уже запускают `vkcube` и Dota 2 на тестовой карте. **Прирост FPS, преимущество над NVIDIA и полная Vulkan conformance не доказаны.**

> Основа: Mesa `26.2.6`, commit `8e87a503ebd91408c88596d1b9eeb5f4c0b2088d`.
> Первый патч: [`gm107-command-cache.patch`](gm107-command-cache.patch). Его исходная, историческая документация: [`README_RU.md`](README_RU.md).
> Следующий этап: [анализ исходников и проект H2](docs/NEXT_PATCH.md), [A/B-протокол](docs/AB_PROTOCOL.md), [проверки инструментов](docs/VALIDATION_V2_PLAN.md).

## Следующий патч: проект H2

Предложено избирательно разрешить продвижение одного часто читаемого UBO с постоянными смещениями во фрагментном шейдере GM107 в аппаратный constant buffer. В текущей базе NVK обычные UBO исключены из этого пути на GPU до Turing из-за стоимости indirect binding. Гипотеза: на тяжёлых fragment workloads экономия shader instructions может окупить привязку.

**H2 пока не реализован и не собран.** Подготовлен конкретный план по функциям Mesa, тестам correctness, shader cache identity и контролю регрессий. Нет доказательства, что Dota использует подходящие шейдеры: это первый проверяемый шаг. Новая библиотека будет собираться от чистого base, отдельно от v0.1.

## Что делает v0.1

Добавляет параметр `NVK_GM107_CMD_CACHE_LIMIT_KIB` (например, `256`): ограничивает кэш **уже освобождённых** LOCAL-capable командных блоков размером 64 KiB в одном Vulkan command pool на чипсете GM107 (`0x117`). Без параметра сохраняется исходная политика. Это **не** глобальный лимит VRAM. Патч может ухудшить производительность, если приведёт к дополнительным выделениям памяти.

## Структура

- `gm107-command-cache.patch` — фактическое изменение исходников NVK (патч к upstream Mesa).
- `build-cachyos.sh` — воспроизводимая локальная сборка исходного и изменённого NVK.
- `bench/` — микротест Vulkan и инструменты анализа frametime.
- `bench/compare_ab.py` — парное сравнение покадровых CSV с bootstrap по прогонам; 12 синтетических тестов. Не проверяет GPU correctness и условия запуска.
- `docs/NEXT_PATCH.md`, `docs/AB_PROTOCOL.md` — текущий план H2 и условия принятия/отказа от гипотезы.
- `README_RU.md`, `docs/ISSUES_TO_CREATE.md` — историческая документация v0.1; её утверждения «Vulkan ещё не запущен» заменены аппаратными отчётами в Issues и статусом выше.
- `logs/` — журналы из исходного переданного архива.
- `RESULTS.json` — **исторический снимок** результатов до аппаратных загрузок (его поля `hardware_tests` / `cachyos_wsi_build` устарели); актуальное состояние описано здесь и в `docs/DEVLOG.md`.
- `SHA256SUMS` — проверки **исходных файлов** архива; новые файлы текущего этапа в этот исторический список не включены.

## Сборка

```bash
bash build-cachyos.sh
```

Скрипт собирает **v0.1**, не H2: исходный и изменённый NVK без установки в систему. Для использования NVK необходим Nouveau; на тестовом ПК уже существуют стабильная NVIDIA-загрузка и отдельная экспериментальная Nouveau/NVK-загрузка. Они сохраняются. Файлы `/boot` и системные конфигурации в репозиторий не включаются.

Проверка нового анализатора без GPU:

```bash
python3 -m unittest discover -s bench -p 'test_compare_ab.py' -v
```

## Участие и ведение журнала

Каждый воспроизводимый результат фиксируем в [`docs/DEVLOG.md`](docs/DEVLOG.md), отдельные задачи — в существующих GitHub Issues. Для новых результатов указываем kernel version, используемый ICD, способ воспроизведения, относящиеся к тесту ошибки, итоги и откат. Не публикуем приватные токены, домашние пути с персональными данными, произвольные дампы памяти.

Лицензии исходных частей определяются их SPDX/лицензиями; Mesa распространяется по своим лицензиям. Этот репозиторий содержит **патч**, а не копию всего дерева Mesa.
