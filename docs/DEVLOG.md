# Development log — GTX 750 Ti NVK experiment

## 2026-11-09 — v0.1: initial source patch and compilation

**Цель.** Изучить драйвер NVK и проверить гипотезу о снижении удержания свободных командных буферов GM107, не меняя управление живыми буферами и Vulkan-синхронизацию.

**Изменение.** Параметр окружения `NVK_GM107_CMD_CACHE_LIMIT_KIB`, применяется только для GM107 (`chipset=0x117`), лимитируется только возвращённый LOCAL-capable кэш *одного* command pool. При значении 256 KiB сохраняется до четырёх блоков по 64 KiB. Значение unset/-1 оставляет исходную политику. Источник — `gm107-command-cache.patch`.

**Проверки.** В переданном архиве сохранены журналы сборки Mesa `26.2.6` из изолированной среды и 11/11 успешных CPU-тестов (включая семь новых сценариев); тест на физическом устройстве в том архиве не выполнен. Позднее пользователь собрал оба варианта на CachyOS: base и patched, с результатами 4/4 и 11/11 CPU-тестов соответственно. Построены файлы `libvulkan_nouveau.so` и два отдельные ICD manifest, они существуют локально, но бинарники не включены в репозиторий (пересобираются из исходников).

**Что НЕ доказано.** Никакого измеренного прироста FPS, сокращения VRAM или реального запуска Vulkan на GTX 750 Ti пока нет. CPU unit tests используют mock backing memory, а не аппаратный GPU.

## 2026-11-09 — Nouveau test boot on CachyOS

**Система.** CachyOS, GTX 750 Ti (GM107, PCI `10de:1380`, 2048 MiB), KDE Wayland. NVIDIA proprietary `580.196.07` в обычном режиме. LTS kernel `6.18.55-2-cachyos-lts`. Тестовая запись Limine создана отдельно, с собственным initramfs, содержащим Nouveau и без NVIDIA-модулей; обычные NVIDIA boot entries сохранены.

**Две аппаратные загрузки Nouveau:**

- 18:32:08–18:33:47 CET, boot ID `71235f97c42449ec9dc2e06dead3ff01`.
- 18:34:21–18:35:08 CET, boot ID `6d16027fd88e4502b513466920c68be6`.

**Подтверждения в journalctl.** Nouveau распознал `NVIDIA GM107 (117000a2)` и `VRAM: 2048 MiB`; драйвер DRM инициализировался. При инициализации есть `bus: MMIO read of 00000000 FAULT at 3e6684 [PRIVRING]`. KWin Wayland сообщил `drmSetClientCap for Atomic Mode Setting failed. Using legacy mode on GPU`, а также `EACCESS` у output layer configuration. В обоих сеансах ядро выдало `gr: DATA_ERROR 00000004 [INVALID_VALUE]` для канала Discord. На рабочем столе наблюдалось **мерцание в чёрный цвет при движениях мышью**. Связь каждого сообщения с мерцанием пока не доказана.

**Безопасность.** Рабочие NVIDIA-загрузки остались доступными; после экспериментов пользователь вернулся в обычный режим. Никаких изменений частот, напряжения, VBIOS или DKMS для экспериментального NVK не требуется.

## Исторический план после первых загрузок (выполнен позднее, см. ниже)

1. Переключиться в тестовый Nouveau boot entry, по возможности в текстовую консоль без KWin/Discord.
2. Подтвердить `lspci -nnk`, `lsmod`, `/dev/dri/renderD*`.
3. Запустить `vulkaninfo --summary` с `VK_DRIVER_FILES` отдельно для исходного и модифицированного NVK; сохранить stderr/stdout и exit code.
4. Если NVK не перечисляет GM107, исследовать аппаратную поддержку в Mesa/NVK и корректно зафиксировать ограничение вместо заявлений о приросте FPS.
5. Если Vulkan работает, сравнить `base`, `patched (unset)` и `patched (256 KiB)` микротестом и повторяемыми frametime-прогонами; контролировать частоты и фоновые приложения.

**Статус на тот момент:** ожидались результаты `vulkaninfo`. Последующие результаты приведены ниже и в Issues.

## 2026-11-09 — сверка всех Issues и проект следующего патча

Прочитаны Issues #1–#4 со всеми комментариями. Поздние отчёты подтверждают перечисление GM107, видимый `vkcube` и запуск Dota 2 на base и v0.1. NVK на тестовом ПК сообщает API 1.3.354. KWin overrides `KWIN_FORCE_SW_CURSOR=1` и `KWIN_USE_BUFFER_AGE=0` вместе устранили видимое мерцание в коротком двухмониторном тесте, включая DP 165 Hz. Отдельная причинность параметров и долговременная стабильность не установлены.

Частоты Nouveau 0f достигали примерно 1012/5400 MHz. Пользователь сообщил лишь около +3 FPS после повышения pstate. На 3-полосном пресете наблюдались ~15 FPS base и ~13 FPS patched, но без контролируемого A/B; это не доказательство регрессии. На 720p сообщались ~22 FPS при 3 полосах и 80–90 на minimum, причём точные условия второго числа требуют воспроизводимого фикса. Steam Overlay off совпал с исчезновением артефактов; ошибки Xwayland DATA_ERROR остаются. Последний комментарий #3 отдельно фиксирует 0% GPU в KDE при реальном рендеринге: показатель нельзя считать фактическим GPU idle.

Аудит исходников Mesa base `8e87a503ebd91408c88596d1b9eeb5f4c0b2088d` и снимка main `5ecabeae8379ca8afb516921ca0fbde397583456` выявил конкретную политику: обычные UBO не продвигаются в cbuf на pre-Turing из-за стоимости indirect push. Предложен H2: opt-in продвижение максимум одного часто используемого constant-offset UBO во fragment shader GM107, с сохранением существующих slots и разделением shader caches.

**Результат этого этапа:** [проект H2](NEXT_PATCH.md), [A/B-протокол](AB_PROTOCOL.md), новый анализатор `bench/compare_ab.py` и 12 успешных синтетических тестов. Исходный v0.1 проходит `git apply --check` на точной базе. **H2 ещё не реализован, не собран и на GPU не запускался; прироста нет среди установленных результатов.** Исходный patch и его исторические журналы сохранены без изменения. Системные драйверы, загрузчик и частоты не изменялись.

При проверке целостности восстановлены только отсутствовавшие конечные LF в 17 архивных файлах: теперь их байты снова совпадают с исходным `SHA256SUMS` (18/18 PASS). Содержание кода/журналов и сам patch не изменены. Подробности — [VALIDATION_V2_PLAN.md](VALIDATION_V2_PLAN.md).
