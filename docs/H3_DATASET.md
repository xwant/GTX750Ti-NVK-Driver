# H3 dataset v1

Implementation: `h3/dataset.py`; CLI `python3 -m h3.dataset --help` from this checkout. Standard library only. Pin Python 3.12 for published reproducibility; no GPU dependency.

## Evidence boundaries

`schema = gm107.dataset.v1`. Records are either **microbenchmark** or **per_shader**, each with independent **synthetic**, **lavapipe**, or **hardware** origin. These fields participate in record identity and are not inferred from optimistic timings. Research refuses mixed origin/scope comparisons. All exported decision/research tables are `driver_ready=false`; no automatic conversion into driver policy exists.

A microbenchmark identity contains scenario group, GPU, Mesa baseline, comparison policies, benchmark binary/SPIR-V digest and configuration. It has **no shader/layout identifiers**. A future per-shader record must explicitly provide shader, layout and compiler SHA-256 identities. These identifiers are absent from current H2 results and may not be fabricated or derived from an arbitrary benchmark label. Hashes identify content, not authenticity or GPU correctness.

Every pair has its index, explicit AB/BA execution order and two uniquely named runs with raw `samples_ns`. v1 accepts 8..1000 pairs, alternating order, equal 2..10000 samples per run, finite positive durations <=1e15 ns; booleans are rejected as numbers. Duplicate records/run IDs, unsupported baselines, unknown fields/schema, out-of-range features, malformed JSON/duplicate JSON keys and incomplete pairs fail. Equal numeric timings in different real runs are allowed; the tool does not infer falsification from repeated numbers.

Canonical output uses sorted object keys/record identities, compact JSON, no timestamps or NaN. Output files are not overwritten. Source artifact hashes are preserved; canonicalization does not alter raw source files.

## Importing H2

`python3 -m h3.dataset import-h2 SUMMARY --runs RESULTS_DIR --manifest MANIFEST --out DATASET`

Legacy aggregate summaries **alone are insufficient**. Import requires their 30-sample CSV captures, successful exit status, launch mode, readback completion and explicit `gm107.h2-import.v1` manifest (actual pair order, evidence origin, GPU, baseline, benchmark identity). Audited H2 collector supplies this manifest. GPU ms are normalized to ns; aggregate means/ratios are cross-checked against raw samples. A mismatched benchmark CONFIG, diagnostic validation timing or software/hardware conflict fails. Hardware imports additionally require the per-run verified library report and matching build checksum.

Manifest provenance is a recorded collector assertion supported by raw artifacts, not cryptographic attestation of a physical GPU or stable clocks. Review calibration conditions and authenticity separately. `artifacts_verified=true` must never be used to relabel a synthetic example as real hardware. Existing summary-only historical files remain archived but are rejected for decision preparation; no missing game identity is filled in.

`.partial.json` files lack completed statistics and cannot be imported. New hardware evidence is generated by `audit/h2-hardware-readiness`; the H3 branch does not contain/install that driver experiment.

## Features

Available from H2 summaries: requested benchmark UBO reads, draw count, known fragment/ordinary-descriptor/constant-access workload. **Requested GLSL reads are not counted NIR UBO loads.** Static UBO loads, machine instructions, GPRs, spills/fills, address-operation counts and compiler-proven cbuf eligibility remain `null` unless separately measured/captured. The importer does not substitute zeros. Total descriptor-layout identity remains unavailable for microbenchmark records.

Future per-shader collection needs canonical late NIR and full descriptor layout semantics (bindings/types/counts/flags, mutable/push/dynamic rules), specialization, robustness, stage, all effective compiler options, exact compiler/transform revisions, output correctness and controlled paired timings. A shader hash without layout/context is not a safe decision key.

## CLI sequence

```sh
python3 -m h3.synthetic --out /tmp/synthetic.json
python3 -m h3.dataset validate /tmp/synthetic.json
python3 -m h3.dataset summary /tmp/synthetic.json
python3 -m h3.dataset decisions /tmp/synthetic.json --out /tmp/research-decisions.json
python3 -m h3.research /tmp/synthetic.json --out /tmp/research.json
```

The first command invents values with an explicit synthetic label to exercise software. No generated nanosecond value is an observed GPU timing. `build INPUT... --out DATASET` merges validated datasets, rejecting reused identities/runs. Eight pairs suffice for descriptive statistics; research evaluation needs **16** to reserve independent calibration/evaluation halves.

Driver build compatibility is explicit in `identity.driver_identities`, keyed by the two compared modes. Hardware values must be SHA-256 identities; off/on must identify the **same binary**, and each policy's identity must stay constant across pairs. Unavailable software/synthetic identities may be null. Research also requires identical benchmark and driver-build identities across the compared scenarios; a common Mesa baseline alone does not establish comparability. Hardware import cross-checks recorded verification/checksum artifacts. These checks enforce consistency of supplied evidence, not external attestation of a device.
